# SchedU

Bilingual university tutorial booking for students, instructors, administrators and a system administrator.

## Product rules

- Accounts use an institutional ID and password. An administrator issues a random initial password. At first login, the user may change it or explicitly keep it.
- Students reserve a time slot, not a specific instructor. Each recurring availability window has an instructor pool, a location and a capacity per slot.
- A staffed slot is approved automatically; an unstaffed slot requires approval.
- Default duration: 10 minutes, with a 5-minute gap. A 18:30–20:05 window ends with a 20:00–20:10 slot excluded because it exceeds the window.
- One active submitted/approved/in-progress booking per student by default. Drafts do not reserve a seat.
- Cancelling a submitted or approved booking blocks new submissions for two weeks by default. Deleting a draft does not incur a penalty.
- Phone numbers are optional, including roster imports. A supplied number must have a valid format. The shared year field is labelled “加入年份” in Chinese for every role.
- Entry year determines freshman status using the current calendar year in China. Administrative class is always mandatory; teaching class is mandatory for freshmen.
- Evaluation options default to 0 (absent), 30 (poor), 40 (satisfactory), 70 (excellent).
- User preferences are saved on the device. Automatic theme follows the browser/system preference.

## Initial setup

The private site presents a one-time administrator setup when no accounts exist. Create the sole institutional system administrator (sysadmin) account, then issue staff accounts, configure instructor availability and import students. No demo student records or default passwords are shipped.

Self-hosted deployments use institutional ID/password login and do not require OpenAI SSO.

## Development

Use Node 22.13 or later. Install with the existing package lock. `npm run dev` starts the local preview; `npm run build` produces the Worker application. Schema migrations are generated by `npm run db:generate` and included in the deployed package.

## Docker deployment

See [DEPLOYMENT.md](DEPLOYMENT.md) for the self-hosted stack, setup, Mainland China/offline deployment, backups and the complete port list. Docker uses institutional login and local SQLite; OpenAI SSO and Cloudflare are not required. The hosted preview remains a separate deployment.

## Administration

- **Accounts:** administrators and the sysadmin can create or import student/instructor accounts, search, edit profiles, change roles, reset passwords and delete unused accounts they manage. Ordinary admins manage students and instructors; the sysadmin additionally manages ordinary admins. People & rosters uses the shared styled dropdowns and shows 50 accounts per page, with numbered pages, first/last controls and direct page entry. An empty teaching class displays “Unassigned Teaching Class / 未分配教学班级”. Status toggles filter All accounts, Booking paused, Active and First login pending. Roster imports have no account-count limit (tested with 1,200 students); the 20 MB request limit remains, and the preview shows the first 50 rows while importing all rows atomically. Select up to 100 accounts for a bulk role change, password reset, deletion or lifting booking pauses. “Lift booking pause” clears the current restriction only for selected paused students; it preserves their sessions, passwords and meeting history. Changing the status filter clears the selection. A failed validation leaves the whole selection unchanged. Meeting records and instructor assignments prevent ordinary account deletion; passwords are shown once for download after a password reset. The sysadmin is excluded from bulk selection and role editing.
- **Permission levels:** the sole `sysadmin` owns global configuration, administrator grants/revocations, full-system export/restore and data reset. An `admin` handles all meetings, schedules, timetable imports and student/instructor rosters, including role changes between student and instructor and password resets. Admins cannot manage other admins or the sysadmin, grant admin access, or change global settings through schedule saves. Instructors handle their assigned sessions and evaluations. Students manage their own bookings and profiles. Permissions are enforced on the server as well as in the interface.
- **Sysadmin lifecycle:** first-time setup creates the sole sysadmin; it is also the only account retained by Reset app data. The database rejects a second sysadmin and prevents deleting, demoting or renaming the sysadmin. Global reset removes ordinary admins too. System-owner replacement occurs only as part of a validated full restoration into a reset system. The sysadmin can change their own profile/password through My profile. On an existing installation, the earliest-created current admin is promoted once because older versions did not record promotion times. New admin grants record their first known grant time and exports preserve it.
- **Teacher cancellation:** Configuration → Booking rules → Allow teachers to cancel assigned bookings defaults to Disabled, including on upgrade and reset. When enabled, assigned instructors may cancel submitted/approved bookings; they cannot cancel unrelated bookings. Teacher and administrator cancellations do not pause the student's future booking rights. The existing student cancellation policy remains unchanged.

- **Classrooms:** the sysadmin uses Configuration → Classrooms to define the room names, one per line. Weekly windows and individual slots select from this list. Existing installations automatically populate the list from rooms already used in schedules; new installations start with an empty list. Update or remove any schedule references before removing a classroom from the list.
- **Semester:** the sysadmin uses Configuration → Semester to set inclusive start/end dates (at most 366 days). Teaching weeks run Monday–Sunday; week 1 contains the start date. Each teaching window has a starting week and an optional repeat count. A blank count runs through semester end; longer counts are clipped to the final date. Dates off do not extend a series. Existing schedules continue as before until a semester is configured. The window form and timetable importer require semester dates for new series.
- **Schedule:** Availability opens a 28-day calendar with previous/next four-week controls, a date jump and a semester-start shortcut. Select any date to manage its slots, including dates beyond the student booking horizon. Expand Weekly teaching windows to add, edit, pause or delete recurring windows. The CSV template accepts `day,instructors,start,end,location,capacity,startWeek,repeatWeeks`; the final two columns are optional, and old six-column files still work. Separate multiple instructor IDs with `;`, and use an exact configured classroom name in `location`. Review recurrence details before importing. Imports reject overlapping assignments in the same teaching weeks, unknown instructors and unconfigured classrooms.
- **Batch removal:** Availability → All semester sessions lists the whole semester, with date-range, weekday, classroom, instructor and teaching-window filters. Select individual rows, one page or every matching session across all pages, then review removal counts. Sessions with submitted, approved or in-progress bookings are always kept, including bookings beyond the current horizon. Unbooked recurring occurrences stay closed; unbooked one-off slots are removed. Weekly window definitions and all booking/history/feedback records remain, and no student cancellation restriction is applied. The server rechecks availability and bookings during the write; concurrent changes require a fresh review. Up to 50,000 sessions can be selected within a 366-day range.
- **Individual slots:** choose a date to edit or close one occurrence, reopen it, or add a one-off slot. Weekly recurrence is unchanged. Semester dates and dates off still apply; only student booking is limited by the booking horizon. Cancel active reservations before changing their time slots; staff cancellations do not penalise students.
- Both languages and the current theme apply to these controls. Teaching-window creation also works on plain HTTP deployments.

- **Reset after testing:** only the sysadmin can use Configuration → Reset app data. Review the scope, type `RESET SchedU` and enter the current sysadmin password. Reset permanently deletes all other accounts (including ordinary administrators), their sessions, all meeting records including feedback/history, and all schedules/custom configuration. Only the sysadmin's account, credentials and profile remain. Reset runs in one guarded transaction and does not reopen first-time setup. Export or back up first; the app has no undo.
- **Server migration:** only the sysadmin can use Configuration → Export & restore. Version 2 JSON packages contain all accounts, password hashes, admin grant times, profiles, restrictions, meetings, feedback/history and configuration, with exactly one sysadmin. The destination must be explicitly reset and unchanged afterwards; restoration replaces all accounts including its temporary sysadmin, never merges, and ends all sessions. Review the incoming sysadmin, type `RESTORE SchedU` and enter the destination sysadmin password. Version 1 packages remain supported: when they have multiple admins, choose which one becomes sysadmin because those exports have no promotion history. A sole legacy admin is selected automatically. Packages are limited to 100 MB with no roster row-count cap. Keep them private. See [the migration instructions](DEPLOYMENT.md#moving-to-another-server-with-an-export-package) for the full workflow and proxy limits.
