# SchedU

Bilingual university tutorial booking for students, instructors and administrators.

## Product rules

- Accounts use an institutional ID and password. An administrator issues a random initial password. At first login, the user may change it or explicitly keep it.
- Students reserve a time slot, not a specific instructor. Each recurring availability window has an instructor pool, a location and a capacity per slot.
- A staffed slot is approved automatically; an unstaffed slot requires approval.
- Default duration: 10 minutes, with a 5-minute gap. A 18:30–20:05 window ends with a 20:00–20:10 slot excluded because it exceeds the window.
- One active submitted/approved/in-progress booking per student by default. Drafts do not reserve a seat.
- Cancelling a submitted or approved booking blocks new submissions for two weeks by default. Deleting a draft does not incur a penalty.
- Phone numbers are optional, including roster imports. A supplied number must have a valid format. The shared year field is labelled “加入年份” in Chinese for every role.
- Entry year determines freshman status using the current calendar year in China. Administrative class is always mandatory; teaching class is mandatory for freshmen.
- Evaluation options default to 0 (absent), 30 (poor), 40 (satisfactory), 70 (excellent).
- User preferences are saved on the device. Automatic theme follows the browser/system preference.

## Initial setup

The private site presents a one-time administrator setup when no accounts exist. Create the institutional administrator account, then issue staff accounts, configure instructor availability and import students. No demo student records or default passwords are shipped.

Keep the hosted site's access private until institutional access and production operation have been reviewed. The Sites access gate and the application's institutional login are separate layers.

## Development

Use Node 22.13 or later. Install with the existing package lock. `npm run dev` starts the local preview; `npm run build` produces the Worker application. Schema migrations are generated by `npm run db:generate` and included in the deployed package.

## Docker deployment

See [DEPLOYMENT.md](DEPLOYMENT.md) for the self-hosted stack, setup, Mainland China/offline deployment, backups and the complete port list. Docker uses institutional login and local SQLite; OpenAI SSO and Cloudflare are not required. The hosted preview remains a separate deployment.

## Administration

- **Accounts:** create or import accounts, search, edit profiles, change roles, reset passwords and delete unused non-admin accounts. People & rosters uses the shared styled dropdowns and shows 50 accounts per page, with numbered pages, first/last controls and direct page entry. An empty teaching class displays “Unassigned Teaching Class / 未分配教学班级”. Status toggles filter All accounts, Booking paused, Active and First login pending. Roster imports have no account-count limit (tested with 1,200 students); the 20 MB request limit remains, and the preview shows the first 50 rows while importing all rows atomically. Select up to 100 accounts for a bulk role change, password reset, deletion or lifting booking pauses. “Lift booking pause” clears the current restriction only for selected paused students; it preserves their sessions, passwords and meeting history. Changing the status filter clears the selection. A failed validation leaves the whole selection unchanged. Meeting records and instructor assignments prevent deletion; passwords are shown once for download after a reset.
- **Admin access:** choose Administrator in an account’s role control to grant full access. Choose Student or Instructor to revoke it. Role changes sign the affected user out. A database guard prevents removing the last administrator, including concurrent or bulk revocations. To leave the administrator role, the sole admin must first grant admin access to another account.
- **Classrooms:** Configuration → Classrooms defines the room names, one per line. Weekly windows and individual slots select from this list. Existing installations automatically populate the list from rooms already used in schedules; new installations start with an empty list. Update or remove any schedule references before removing a classroom from the list.
- **Schedule:** the default view is a dated calendar of the next 28 days, with instructors, locations, remaining seats, dates off and one-off changes. Select a date to manage its slots. Expand Weekly teaching windows to add, edit, pause or delete recurring windows. The timetable CSV template accepts `day,instructors,start,end,location,capacity`; separate multiple instructor IDs with `;`, and use an exact configured classroom name in `location`. Review the preview before importing. Imports append windows and reject overlapping assignments, unknown instructors or unconfigured classrooms.
- **Individual slots:** choose a date to edit or close one occurrence, reopen it, or add a one-off slot. Weekly recurrence is unchanged. Dates off and the booking horizon still apply. Cancel active reservations before changing their time slots; staff cancellations do not penalise students.
- Both languages and the current theme apply to these controls. Teaching-window creation also works on plain HTTP deployments.

- **Reset after testing:** Configuration → Reset app data shows the full scope before asking for `RESET SchedU` and the current administrator password. It permanently deletes all meeting records (including feedback/history), non-admin accounts and their sessions, weekly windows, individual slot changes and closed dates. It restores default configuration and clears booking pauses. All administrator accounts, passwords and profiles remain. Reset runs as one transaction, with administrator access rechecked at the point of deletion. Make a database backup first; the app has no undo. Regular per-account deletion and booked-slot protection remain in place.
